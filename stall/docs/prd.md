## 1. 产品概述

### 1.1 背景
烧烤摊、夜市小摊等摊主在高峰期面临的核心问题是：**手写记单慢、加单容易乱、漏单算错账、顾客催单无法及时响应**。摊主双手忙于出餐，无法频繁操作手机或纸笔。现有餐饮 SaaS 功能冗余、价格高、绑定支付，不适合无固定店面的摊主。

### 1.2 产品定位
一款**不涉及在线支付**的摊主点单与桌台管理工具。顾客可扫码点单，摊主可代客下单；系统负责记录订单、叠加加单、语音播报、呼叫提醒、出餐叫号、清台重置。**资金交易完全由摊主线下自行完成**，产品只解决"点单效率"和"桌台秩序"问题。

### 1.3 核心价值
> 帮摊主在高峰期记住每一单、加对每一单、叫对每一桌，不漏单、不算错、不手忙脚乱。

### 1.4 产品边界
| 做 | 不做 |
|---|---|
| 点单、加单、退单 | 在线支付、收款 |
| 桌号状态管理、清台 | 对接微信支付/支付宝 |
| 语音播报、呼叫提醒 | 打印小票（V1不做，V2可选） |
| 菜品管理、简单统计 | 后厨分单、供应链、会员营销 |
| 顾客扫码点单 | 多商家平台、抽佣 |

## 2. 目标用户与场景

### 2.1 目标用户
- **主要用户**：烧烤摊、夜市小吃摊、流动摊贩等单人/双人经营的摊主。
- **次要用户**：小型餐饮店（1-3人），需要轻量点单工具。
- **顾客**：到摊消费的食客，习惯口头点单或愿意扫码点单。

### 2.2 典型场景
1. **摊主代客下单**：顾客口头点单，摊主在 App 上快速选菜、提交，语音播报确认。
2. **顾客扫码点单**：顾客扫桌边二维码，浏览菜单、选菜、提交，摊主端语音播报。
3. **加单**：顾客吃到一半要加菜，摊主在原有订单上直接追加，或顾客再次扫码加单。
4. **呼叫摊主**：顾客需要纸巾、加料、结账，点击"呼叫"，摊主端震动+语音提醒。
5. **出餐叫号**：菜品制作完成，摊主点"完成"，系统语音叫号"X号桌取餐"。
6. **清台**：顾客离场，摊主确认线下收款后，手动清台，桌号释放给下一桌。

## 3. 核心概念与状态定义

### 3.1 桌号
每个摊位可设置若干桌号（如1-20号），每个桌号对应一张二维码贴纸。

### 3.2 桌号状态机
```
空闲 → 开台（第一笔订单）→ 用餐中（可加单）→ 待清台 → 清台 → 空闲
```
| 状态 | 说明 |
|---|---|
| 空闲 | 桌号可用，扫码或摊主选桌时创建新订单 |
| 开台 | 第一笔订单已提交，桌号被占用 |
| 用餐中 | 顾客可加单，订单持续累加 |
| 待清台 | 所有菜品已出餐，等待摊主确认清台 |
| 清台 | 订单归档，桌号释放 |

### 3.3 订单
- 一个桌号在同一时段内只有一个**活跃订单**。
- 所有加单都合并到该活跃订单中，账单自动累加。
- 清台后，活跃订单归档为历史订单，桌号创建新订单。

## 5. 核心流程

### 5.1 摊主代客下单流程
```
1. 摊主打开App，首页显示桌号卡片。
2. 点击空闲桌号（如5号桌），进入点单界面。
3. 选择菜品、规格、数量，加入购物车。
4. 提交订单，语音播报"5号桌，羊肉串x10，鸡翅x5……"
5. 桌号卡片变为"用餐中"，显示总价。
```

### 5.2 顾客扫码点单流程
```
1. 顾客扫描桌边二维码，进入小程序点单页。
2. 浏览菜单，选菜，加入购物车。
3. 提交订单，页面提示"已提交，请等待"。
4. 摊主端语音播报新订单。
5. 摊主接单，开始制作。
```

### 5.3 加单流程
```
1. 顾客口头加单，或再次扫码加单。
2. 摊主在订单详情页点击"加菜"，选择菜品提交。
3. 语音播报"5号桌加单，鸡翅x5"。
4. 订单总价自动累加。
```

### 5.4 呼叫流程
```
1. 顾客点击"呼叫摊主"。
2. 摊主端对应桌号卡片闪烁，手机震动，语音播报"5号桌呼叫"。
3. 摊主点击卡片，提醒消失。
```

### 5.5 出餐叫号流程
```
1. 摊主制作完成，在订单详情页点击"完成出餐"。
2. 语音播报"5号桌取餐"。
3. 该桌所有菜品标记为已出餐，桌号状态变"待清台"。
```

### 5.6 清台流程
```
1. 顾客离场，摊主确认线下收款。
2. 摊主在订单详情页点击"结账并清台"。
3. 弹窗提示："5号桌消费128元，确认清台？"
4. 摊主确认。
5. 订单归档，桌号变"空闲"，语音播报"5号桌已清台"。
```

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 语音播报延迟 < 1秒；订单提交响应 < 2秒 |
| 可靠性 | 语音播报必须稳定，支持后台运行；网络不稳定时订单先本地缓存，恢复后同步 |
| 兼容性 | 摊主端支持 Android / iOS；顾客端支持微信小程序 |
| 易用性 | 摊主端操作路径不超过3步完成点单；字体大、按钮大，适合油烟环境 |
| 数据安全 | 订单数据云端备份，摊主可导出历史订单 |
| 合规 | 不涉及资金交易，不申请支付牌照，不碰二清 |

## 7. 版本规划

### V1.0（核心版）
- 摊主端：登录、菜品管理、桌台管理、点单、加单、退单、语音播报、呼叫提醒、出餐叫号、清台、历史订单、今日统计。
- 顾客端：扫码点单、加单、呼叫摊主、查看已点。
- 收费模式：免费版（基础点单+手动记单），付费版（语音播报+加单叠加+统计）年费199元或买断499元。

### V1.1（优化版）
- 蓝牙小票打印（付费增值）。
- 换桌/并桌。
- 多设备同步（摊主+帮工）。
- 数据导出。

### V2.0（扩展版）
- 会员储值（仅记录，不支付）。
- 预约自提。
- 多摊位管理。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 摊主觉得"手写也行" | 强调语音播报+加单叠加的效率优势，提供免费版试用 |
| 顾客扫码意愿低 | 摊主代客下单为主，扫码为辅 |
| 语音播报在嘈杂环境听不清 | 支持音量调节、震动提醒、屏幕高亮 |
| 网络不稳定 | 本地缓存订单，恢复后同步 |
| 误清台 | 二次确认弹窗，显示未出餐菜品 |
